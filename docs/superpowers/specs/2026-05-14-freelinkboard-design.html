FreeLinkBoard 第一版设计规格

创建日期：2026-05-14。最后更新：2026-05-15。状态：设计讨论中，用户确认一段就同步更新一段。

1. 产品边界

FreeLinkBoard 第一版是一个本地单人白板笔记软件。它不是协作文档，也不是通用绘图软件；它的核心是让用户用最少动作创建文本节点、延展节点关系、画出有方向感的蓝图式连线。

第一版支持多个本地白板文件。每张白板保存为一个独立的 .flb 文件，用户可以从应用内最近白板列表打开，也可以从系统文件夹直接打开文件。新建白板不会覆盖旧白板。

第一版只做纯文本节点和关系线，不做矩形、圆形、自由画笔、富文本、Markdown、云同步、多人协作。未来会预留图片节点、URL 节点、PDF 节点、分组、列表和同步能力的扩展空间。

3. 画布交互设计

第一版的画布交互要尽量像“手已经知道该怎么做”，不依赖复杂模式切换。默认状态下，左键负责选择和编辑对象，右键负责移动视野，快捷键负责生成关系。

节点创建与编辑

用户在空白处双击时，系统创建一个纯文本节点，并立即进入编辑状态。用户不需要先画框，也不需要再点一次；光标已经在节点里，可以直接输入。节点默认根据内容自动撑开。如果用户拖过节点边缘，节点进入固定尺寸模式，后续文字在框内自动换行。

已有节点上，单击表示选中，双击表示进入文字编辑，按住左键拖动表示移动。创建节点后的首次输入是一个特殊例外：创建即编辑。编辑结束可以通过 Esc、点击空白处，或者按 Tab 创建下一个相连节点。

Tab 创建相连节点

Tab 是“继续思考”的动作。当一个节点被选中，或者用户正在编辑一个节点时，按 Tab 会结束当前编辑，在附近找一个不拥挤的位置创建新节点，并自动连线到它。新节点创建后立即进入编辑状态，让用户可以连续输入一串想法。

Ctrl+L 拉关系线

Ctrl+L 是“拉关系线”的动作，必须先选中一个节点。按下后进入连线预览，线从节点边缘伸出并跟随鼠标移动。点击另一个节点时，线吸附到目标节点；点击空白处时，线终点固定在白板位置。按 Esc 取消连线创建。默认新线是蓝图风格曲线，并带单向箭头。

线编辑与固定点

单击线会选中该线，并在线旁浮出样式工具条。双击线上的某个位置，会在该位置插入一个可拖动固定点。固定点平时不显示，只有悬停线或选中线时出现。拖动固定点时，线会被该固定点牵引并重新计算路径。选中固定点后按 Delete 可以删除它。

框选、拖动画布与缩放

空白处左键拖动用于框选。框选后可以一组移动节点，相关连线跟随节点位置重新计算。空白处右键拖动用于平移画布。默认 Ctrl + 滚轮 缩放，缩放以鼠标位置为中心；设置里可以切换为滚轮直接缩放。

输入与命中优先级

正在编辑文字时，键盘输入优先交给文字节点；Esc 退出编辑；Tab 被定义为创建相连节点，不插入制表符。鼠标命中优先级为：固定点、线、节点、空白画布。这样用户拖动固定点时不会误选整条线，选择线时也不会误触空白画布。

4. 数据模型和 .flb 文件格式

第一版的 .flb 文件使用可读 JSON 文本格式。文件保存白板元信息、视口状态、节点列表和连线列表。这样即使应用出现问题，用户或开发者也能直接打开文件检查内容，后续迁移和兼容也更容易。

顶层结构

{
  "version": 1,
  "title": "游戏系统图",
  "createdAt": "2026-05-14T12:00:00.000Z",
  "updatedAt": "2026-05-14T12:30:00.000Z",
  "viewport": {
    "x": 0,
    "y": 0,
    "zoom": 1
  },
  "nodes": [],
  "edges": []
}

这里的 JSON 是持久化 DTO，不要求和应用内 Domain Model 逐字段一致。Loader 会把文件中的 x、y、width、height 映射为 Domain 层的 position 和 size；Saver 会把 Domain 状态输出为稳定、可读的文件结构。

节点结构

节点必须包含 type，第一版只实现 text，但结构上允许未来扩展 image、url、pdf、group 等节点类型。

{
  "id": "node_1",
  "type": "text",
  "x": 120,
  "y": 180,
  "width": 160,
  "height": 56,
  "sizing": "auto",
  "text": "背包系统",
  "style": {
    "borderColor": "#24221f",
    "backgroundColor": "#fffdf8",
    "textColor": "#24221f"
  }
}

sizing 用来区分节点尺寸状态。auto 表示节点根据文字内容自适应；fixed 表示用户手动拖过大小，文字在框内换行。

连线结构

连线两端既可以连接节点，也可以落到白板上的固定点。这样 Ctrl+L 拉线时，点击节点和点击空白处都能用同一种数据结构保存。

{
  "id": "edge_1",
  "from": {
    "type": "node",
    "id": "node_1"
  },
  "to": {
    "type": "point",
    "x": 420,
    "y": 220
  },
  "pathType": "bezier",
  "arrow": "end",
  "stroke": {
    "color": "#2f6f6a",
    "width": 2,
    "dash": "solid"
  },
  "fixedPoints": [
    {
      "x": 280,
      "y": 130
    }
  ]
}

pathType 支持 bezier、straight、roundedElbow。arrow 支持 none、end、both。stroke.dash 支持 solid 和 dashed。fixedPoints 保存用户双击线后加入的固定点。

兼容策略

文件包含 version 字段。第一版读取文件时只承诺支持 version: 1，后续如果引入附件包、图片资源或同步元数据，可以通过版本迁移升级。第一版不保存撤销历史，只保存白板最终状态。

5. 代码架构与设计模式

第一版采用 Clean Architecture / Hexagonal Architecture 思路：核心白板逻辑不依赖 Electron、React、DOM、文件系统或第三方服务。React 是表现层，Electron 是桌面与文件系统适配器，核心业务通过接口、策略和命令向外暴露能力。

推荐方案是 Clean/Hexagonal Architecture + Command + Strategy + Repository + 依赖注入。这样可以同时满足低耦合、可测试、可扩展。暂不采用完整事件溯源或插件系统，因为第一版会过重；也不直接套通用白板库，因为 FreeLinkBoard 的 Tab 生节点、Ctrl+L 拉线、双击线插固定点等交互非常定制。

架构边界

  • Domain 层定义白板实体、值对象和业务接口，不依赖任何外部系统。
  • Application 层承载用例、命令、撤销重做、保存调度等应用逻辑。
  • Infrastructure 层实现文件系统、Electron IPC、配置读写等外部适配器。
  • Presentation 层由 React 组件组成，只负责渲染状态和把用户输入转成应用用例调用。
  • Composition 层负责组装依赖，把具体实现注入到用例和服务中。

核心设计模式

模式 用途
Command 创建节点、移动节点、编辑文字、创建线、插入固定点、改线样式等修改操作都封装为命令。命令提供 execute 和 undo，保证撤销重做稳定。
Strategy Tab 新节点找空位、线径生成、线命中测试、箭头渲染等行为通过策略扩展。后续可替换更聪明的布局算法或更多线型。
Repository 文档读写通过 DocumentRepository 抽象隔离。第一版实现 Electron 本地文件仓库，未来可替换为云同步仓库或内存仓库。
Dependency Injection 核心服务依赖接口，不直接 new 外部实现。应用启动时统一组装依赖，单元测试时可以注入假实现。
State Store 白板内容、文件保存状态、界面临时状态拆成不同 store，避免 React 组件直接持有复杂业务逻辑。

Command 示例

export interface BoardCommand {
  name: string;
  execute(state: BoardState): BoardState;
  undo(state: BoardState): BoardState;
}

export class CreateLinkedTextNodeCommand implements BoardCommand {
  name = "create-linked-text-node";

  private createdNode?: TextNode;
  private createdEdge?: BoardEdge;

  constructor(
    private readonly sourceNodeId: NodeId,
    private readonly ids: IdGenerator,
    private readonly placement: NodePlacementStrategy,
    private readonly defaults: BoardDefaults
  ) {}

  execute(state: BoardState): BoardState {
    const sourceNode = state.nodes[this.sourceNodeId];
    if (!sourceNode) return state;

    const position = this.placement.placeNextNode({
      sourceNode,
      existingNodes: Object.values(state.nodes),
      preferredSize: this.defaults.textNodeSize
    });

    this.createdNode = {
      id: this.ids.next("node"),
      type: "text",
      position,
      size: this.defaults.textNodeSize,
      sizing: "auto",
      text: ""
    };

    this.createdEdge = {
      id: this.ids.next("edge"),
      from: { type: "node", nodeId: sourceNode.id },
      to: { type: "node", nodeId: this.createdNode.id },
      pathType: this.defaults.edgeStyle.pathType,
      arrow: this.defaults.edgeStyle.arrow,
      stroke: this.defaults.edgeStyle.stroke,
      fixedPoints: []
    };

    return {
      ...state,
      nodes: { ...state.nodes, [this.createdNode.id]: this.createdNode },
      edges: { ...state.edges, [this.createdEdge.id]: this.createdEdge },
      selection: { nodeIds: [this.createdNode.id], edgeIds: [] }
    };
  }

  undo(state: BoardState): BoardState {
    if (!this.createdNode || !this.createdEdge) return state;
    const { [this.createdNode.id]: removedNode, ...nodes } = state.nodes;
    const { [this.createdEdge.id]: removedEdge, ...edges } = state.edges;
    return { ...state, nodes, edges };
  }
}

History Service 示例

export class HistoryService {
  private undoStack: BoardCommand[] = [];
  private redoStack: BoardCommand[] = [];

  constructor(private state: BoardState) {}

  run(command: BoardCommand): BoardState {
    this.state = command.execute(this.state);
    this.undoStack.push(command);
    this.redoStack = [];
    return this.state;
  }

  undo(): BoardState {
    const command = this.undoStack.pop();
    if (!command) return this.state;
    this.state = command.undo(this.state);
    this.redoStack.push(command);
    return this.state;
  }
}

Strategy 示例

export class NearestFreeSpaceStrategy implements NodePlacementStrategy {
  constructor(private readonly config: { gap: number; searchStep: number }) {}

  placeNextNode(input: {
    sourceNode: BoardNode;
    existingNodes: BoardNode[];
    preferredSize: { width: number; height: number };
  }): Point {
    const base = input.sourceNode.position;
    const candidates = [
      { x: base.x + input.sourceNode.size.width + this.config.gap, y: base.y },
      { x: base.x, y: base.y + input.sourceNode.size.height + this.config.gap },
      { x: base.x, y: base.y - input.preferredSize.height - this.config.gap }
    ];

    return candidates.find(point => !this.collides(point, input)) ?? candidates[0];
  }

  private collides(point: Point, input: {
    existingNodes: BoardNode[];
    preferredSize: { width: number; height: number };
  }): boolean {
    return input.existingNodes.some(node =>
      point.x < node.position.x + node.size.width &&
      point.x + input.preferredSize.width > node.position.x &&
      point.y < node.position.y + node.size.height &&
      point.y + input.preferredSize.height > node.position.y
    );
  }
}

SOLID 约束

  • 单一职责：React 组件不处理文件系统，Geometry 不处理 React 渲染，Command 不处理弹窗和菜单。
  • 开闭原则：新增节点类型、线型、布局算法时优先新增策略或渲染器，不修改既有核心流程。
  • 依赖倒置：Application 层依赖 DocumentRepository、NodePlacementStrategy、IdGenerator 等接口，不依赖 Electron 或具体库。
  • 接口隔离：文件读写、ID 生成、线径计算、节点放置分别是小接口，不做巨大万能服务。
  • 可测试性：核心逻辑用内存仓库、固定 ID 生成器、假策略即可测试，不需要启动 Electron 或浏览器。

6. 核心渲染方案

第一版采用高性能混合渲染方案：HTML/React 负责可编辑节点，Canvas 负责背景和连线批量绘制，轻量 Overlay 负责当前交互状态。白板内部使用统一世界坐标系，节点位置、线端点、固定点都保存为白板坐标；缩放和平移只改变 viewport.x、viewport.y、viewport.zoom。

渲染分层

BoardViewport
  GridCanvasLayer          背景网格，Canvas 绘制
  EdgeCanvasLayer          可见线、箭头、虚线、路径，Canvas 绘制
  NodeDomLayer             只挂载视口内 HTML/React 节点
  InteractionOverlayLayer  框选、连线预览、固定点、工具条、搜索高亮

节点仍然使用 HTML/React 渲染，因为文本编辑、自适应尺寸、输入法、复制粘贴，以及未来图片、URL、PDF 卡片扩展都更自然。但节点层必须做视口裁剪，只挂载视口内或视口附近缓冲区内的节点，视口外节点只保留在 store 和空间索引中。

连线使用 Canvas 绘制，而不是每条线一个 SVG path。线的路径、箭头、虚线、颜色、粗细和固定点影响的曲线都由 Geometry 层计算，再由 Canvas 批量绘制。这样在大量线条和频繁缩放平移时，性能上限更高。

高性能机制

  • 空间索引：节点和线都维护 bounds，并放入 R-tree 或等价空间索引。渲染、框选、命中测试优先从索引取候选对象。
  • 视口裁剪：DOM 节点只渲染可见节点，Canvas 线层只绘制可见线。远处对象不参与当前帧渲染。
  • 路径缓存：每条线的几何路径缓存起来。只有节点移动、固定点变化、线样式变化或端点变化时才重新计算。
  • LOD 简化：缩放很小时，节点显示为简化矩形和短标题，隐藏完整文本和细节；线也可以降低绘制细节。放大后恢复完整显示。
  • 交互层分离：拖动节点、框选矩形、连线预览、固定点小圆点、浮动工具条放在轻量 Overlay 中，避免触发整张白板 React 重渲染。
  • 渲染调度：滚动、缩放、拖拽等连续交互通过 requestAnimationFrame 合批绘制。保存和索引重建不能阻塞当前帧。

命中测试

节点点击可以使用 DOM 事件作为入口，但线和固定点不依赖 DOM path。HitTestService 会把鼠标位置转换为白板坐标，先通过空间索引找附近候选线，再计算鼠标到曲线或折线的距离。这样即使线由 Canvas 绘制，也能支持悬停、选中、双击插入固定点和拖动固定点。

可替换渲染后端

第一版使用 Canvas2D 实现连线渲染，但通过接口隔离，后续可以替换为 PixiJS/WebGL 或其他 GPU 渲染后端，而不改业务层。

纯 HTML/SVG 实现简单，但大图上限较低，不作为第一版最终方案。
全 Canvas/Pixi 性能最高，但文本编辑和未来卡片节点复杂，不适合 FreeLinkBoard 的核心体验。
HTML 节点 + Canvas 线层 节点编辑自然，线条批量绘制高效，是第一版推荐方案。

7. 测试与质量策略

第一版把“手感”和“文件安全”作为质量核心。测试目标不是只证明按钮能点，而是证明节点不会丢、连线不会乱、撤销可靠、大图不会拖垮应用。

单元测试

核心逻辑必须脱离 React、Electron、DOM 和真实文件系统单测。测试中使用固定 ID 生成器、假仓库、假时间和内存数据。

  • Geometry：节点边缘连接点、贝塞尔曲线路径、直线路径、圆角折线路径、固定点插入、鼠标到线距离、框选相交。
  • PlacementStrategy：按 Tab 后找附近空位，不压到已有节点；拥挤时能继续扩散。
  • Command/History：创建节点、移动节点、编辑文本、创建线、插入固定点、改线样式、删除对象都能 execute、undo、redo。
  • Document：.flb 读取、默认值补齐、坏文件报错、保存后再读取内容一致。
  • SpatialIndex：视口查询、框选查询、移动节点后索引更新正确。

集成测试

集成测试验证多个核心模块组合后的行为。这里使用真实 application service 和内存版 DocumentRepository，不需要启动 Electron。

  • 创建节点后自动进入编辑状态。
  • 编辑节点时按 Tab，会新建节点、自动连线、选中新节点。
  • Ctrl+L 从节点拉线，落到节点或空白点都能生成正确 edge。
  • 双击线插入固定点，拖动固定点后路径更新。
  • 自动保存防抖生效，Ctrl+S 立即保存。
  • 搜索当前白板节点后，视口能跳到结果并高亮。

端到端测试

端到端测试使用 Electron + Playwright 覆盖最关键的真实流程。

  • 新建白板，双击建节点，输入文字，按 Tab 新建相连节点。
  • 选中节点，按 Ctrl+L，点击另一个节点，生成默认曲线单向箭头。
  • 双击线，出现固定点，拖动固定点，保存并重新打开后固定点仍在。
  • 框选多个节点，整体移动，撤销后恢复原位。
  • 保存 .flb，关闭，从最近文件打开后内容和视口恢复。
  • Ctrl+F 搜索节点，命中节点居中并高亮。

性能验收

  • 加载包含 5,000 个节点、8,000 条线的测试白板时，应用不能卡死。
  • 平移和缩放时只渲染视口内对象，不能把全量节点挂进 DOM。
  • 视口内约 300 个节点、800 条可见线时，拖动画布要保持接近流畅。
  • 移动单个节点时，只重算相关连线和必要索引，不全量重算所有线。
  • 保存大文件时不能阻塞当前交互到明显冻结。

人工手感验收

自动测试之外，需要保留一张手感检查表。检查项包括：双击创建是否足够快，Tab 连续输入是否像思路自然延展，Ctrl+L 拉线是否有迟滞，线的固定点是否容易命中但平时不碍眼，多选和拖动画布是否不冲突。

8. 第一版实施范围和里程碑

第一版包含本文档中已经确认为 1.0 核心范围的功能。文档中标记为未来扩展或预留口子的能力不纳入第一版交付，例如图片节点、URL 节点、PDF 节点、分组、列表、云同步、多人协作、评论、分享、插件系统、.flb 包格式和内置附件。

第一版不是临时玩具 MVP，而是一个能真实使用的本地白板核心版。范围保持克制，但节点与连线的核心手感必须完整。

M0：工程地基

  • 搭建 Electron + React + TypeScript 工程。
  • 配置测试、代码规范、构建流程和基础窗口。
  • 建立 Domain、Application、Infrastructure、Presentation 的架构边界。
  • 定义 BoardState、.flb schema、Command、History、Geometry 接口。

M1：本地文件与首页

  • 实现最近白板列表、新建白板、打开 .flb、保存 .flb。
  • 实现自动保存和 Ctrl+S 立即保存。
  • 白板页显示保存状态：未保存、保存中、已保存。

M2：高性能画布骨架

  • 实现世界坐标系、视口平移缩放、背景 Canvas。
  • 实现 NodeDomLayer、EdgeCanvasLayer、InteractionOverlayLayer。
  • 实现空间索引、视口裁剪、路径缓存和基础 LOD。
  • 用假节点和假线压测，确认大白板不会一开始就卡住。

M3：文本节点核心交互

  • 双击空白创建文本节点，创建后立即编辑。
  • 节点支持单击选中、双击编辑、左键拖动。
  • 节点默认自适应文字，手动 resize 后锁定尺寸。
  • 支持框选、多选移动、撤销重做。

M4：蓝图式连线核心交互

  • Tab 找附近空位创建相连节点。
  • Ctrl+L 从节点拉线，点击节点连接，点击空白处落点。
  • 默认线是蓝图曲线 + 单向箭头。
  • 支持直线、曲线、圆角折线。
  • 支持无箭头、单向箭头、双向箭头。
  • 支持实线、虚线、颜色和粗细。
  • 实现选中线浮动工具条。
  • 实现双击线插入固定点，悬停或选中线时显示固定点，拖动固定点调整线路。

M5：搜索、设置与体验收口

  • Ctrl+F 搜索当前白板文本节点，定位并高亮。
  • 设置默认 Ctrl + 滚轮 缩放，可切换滚轮直接缩放。
  • 支持线默认颜色和粗细设置。
  • 补齐删除、复制粘贴、基础快捷键提示、关闭前保存检查。

M6：性能、稳定性与打包

  • 构造 5,000 节点、8,000 线的测试白板。
  • 检查视口裁剪、路径缓存、索引更新、拖动性能和保存大文件体验。
  • 跑单元测试、集成测试、端到端测试和性能验收。
  • 打包 Windows 桌面版。

第一版验收标准：能作为用户自己的日常画图笔记工具使用一周，不需要靠“以后会修”来忍受核心操作。

9. 风险与关键技术验证

第一版最主要的风险不是功能做不出来，而是功能做出来但手感不稳。因此以下风险需要在对应里程碑中主动验证，而不是等到最后收尾时再处理。

Canvas 线层和 HTML 节点层坐标不同步

节点在 DOM，线在 Canvas。如果 viewport transform、devicePixelRatio、滚动偏移处理不一致，会出现线端点和节点边缘对不齐。

验证方式：M2 阶段建立坐标测试页，放置几十个节点和线，在不同缩放比例、窗口尺寸和系统缩放下检查端点是否贴合。自动测试覆盖 world/screen 坐标互转。

线命中测试不准

线由 Canvas 绘制，不能依赖 DOM path 命中。双击线插固定点、悬停显示固定点、选中线工具条都依赖命中测试。命中区域太窄会让软件显得不听话，太宽又会误选。

验证方式：Geometry 层单测鼠标到直线、折线、贝塞尔曲线的距离。人工测试不同粗细、缩放比例下是否容易点中。命中半径应按屏幕像素保持稳定，视觉上约 8 到 12 像素。

Tab 找空位算法太傻

用户连续按 Tab 时，新节点如果乱跳、压住已有节点，或者总是挤到奇怪方向，会破坏“思路自然生长”的感觉。

验证方式：准备空白场景、右侧拥挤场景、四周都有节点场景、节点大小不同场景。第一版算法可以简单，但结果必须可预期：优先找近处，避开重叠，方向变化不要突然。

中文输入法和快捷键冲突

节点编辑是纯文本。中文输入法组合态下，如果 Enter、Esc、Tab 处理不当，可能打断输入。

验证方式：编辑层明确处理 compositionstart 和 compositionend，组合输入期间不触发白板快捷键。手测中文、英文、复制粘贴、多行文本和文本编辑撤销。

自动保存导致卡顿或文件损坏

大白板 JSON 可能较大。如果每次移动节点都保存，画布会卡。如果写文件中途崩溃，可能损坏原文件。

验证方式：保存层使用防抖和原子写入，先写临时文件，再替换正式文件。大文件保存走异步流程，保存状态可见。测试保存失败时不破坏旧文件。

Command/History 粒度不合适

拖动节点时，如果每移动 1 像素都是一个命令，撤销会失控；如果整个编辑过程合成不对，撤销又不符合用户预期。

验证方式：定义命令合并规则。拖动开始到拖动结束合成一个 MoveNodesCommand；文本编辑提交时形成一个 EditNodeTextCommand；连续样式切换按用户动作入栈。用单测覆盖撤销粒度。

大图性能被 React 重渲染拖垮

如果节点拖动、缩放、选中线时触发整张白板 React 重渲染，大图会抖动或卡顿。

验证方式：M2 开始建立性能基准，监控 DOM 节点数量、渲染帧时间、索引更新时间。节点组件 memo 化，只挂载视口内节点，连续交互通过 requestAnimationFrame 合批。

文件格式以后扩展困难

第一版是 JSON .flb，未来可能要图片节点、附件和同步。如果第一版字段写死，未来扩展成本会高。

验证方式：保留 version、node.type、edge.pathType、可选 metadata。Loader 必须能补默认值，Saver 输出干净结构。UI 临时状态不能混入文件。

浮动工具条遮挡或跳动

线工具条如果一直挡住节点，或者缩放时位置跳动，会影响编辑手感。

验证方式：工具条位置由选中对象 bounds 和 viewport 计算，保持屏幕尺寸，不随 zoom 缩小。靠近窗口边缘时自动换边。人工测试密集线条场景。

本地桌面体验不完整

如果最近文件失效、移动文件后打不开、关闭前没保存提示，用户会失去对本地文件软件的信任。

验证方式：最近文件打开前检查路径存在；文件不存在时提示移除；未命名白板关闭前询问保存；已命名白板依靠自动保存和最后一次保存状态提示。
