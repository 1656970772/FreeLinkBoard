# 缩放鼠标锚点修复

## 用户反馈

- 用户指出 Ctrl/Meta + 滚轮缩放时，需要以鼠标位置为准，体验应类似虚幻引擎蓝图编辑器。
- 用户观察到当前缩小和放大后，鼠标位置正在看的节点会偏离甚至出屏幕。

## 调试记录

- 来源：`src/application/geometry/viewportTransform.ts` 中 `zoomViewportAtScreenPoint` 已经按“缩放前鼠标下的世界点，缩放后仍在同一屏幕点”计算 viewport。
- 来源：`tests/application/geometry/viewportTransform.test.ts` 已覆盖几何层的鼠标锚点缩放。
- 来源：`tests/renderer/board/BoardCanvas.interactions.test.tsx` 之前只检查 `zoom 1.10`，没有检查 `viewport.x/y` 与节点屏幕位置。
- 我的判断：几何公式本身不是根因；风险点在滚轮交互层用渲染闭包里的旧 `viewport.zoom` 计算下一步 zoom。连续滚轮事件可能不按最新 viewport 累积，用户会感觉缩放锚点和预期不一致。

## 修复内容

- 在 `useCanvasViewport` 增加 `zoomByScreenPoint(screenPoint, zoomFactor)`，在 `setViewport` updater 内基于最新 `current.zoom` 计算下一步缩放。
- `BoardCanvas` 的滚轮处理改为调用 `zoomByScreenPoint`，并复用 `getLocalScreenPoint` 计算画布局部鼠标位置。
- 新增 hook 回归测试：连续两次 `1.1` 缩放应累积到 `1.21`。
- 新增画布交互回归测试：Ctrl+滚轮缩放后 overlay 应出现 `x 29 y 16 zoom 1.10`，节点 transform 仍停在鼠标锚点对应位置。

## 验证

- `npm.cmd test -- tests\renderer\board\useCanvasViewport.test.ts` 先红灯：`zoomByScreenPoint is not a function`。
- 修复后 `npm.cmd test -- tests\renderer\board\useCanvasViewport.test.ts tests\renderer\board\BoardCanvas.interactions.test.tsx` 通过，25 个测试通过。
- 浏览器 smoke：在 `http://127.0.0.1:5173/` 新建节点后，在节点中心连续两次 Ctrl+滚轮，overlay 从 `zoom 1.00` 到 `zoom 1.21`，节点中心与鼠标坐标偏差约 0。
- 完整验证：`npm.cmd test` 通过，15 个测试文件、82 个测试通过；`npm.cmd run typecheck` 通过；`git diff --check` 通过，仅有 CRLF 提示。
