# 2026-05-15 FreeLinkBoard M3 交互问题修复记录

## 用户反馈

- 双击创建后输入多行文本时，文本框没有实时自适应，只在 blur 后变大。
- 自动尺寸留白偏多，三行文本高度不紧凑。
- 普通滚轮也会缩放，预期是 `Ctrl + 滚轮` 缩放。
- 节点左键拖动不丝滑，拖动过程中节点不动，松手后瞬移。
- 反复拖动后出现节点消失现象，用户提供了录屏：`C:/Users/Administrator/Videos/屏幕录制/屏幕录制 2026-05-15 152258.mp4`。

## 根因判断

- `NodeTextEditor` 只在 `blur` 时通过 `onTextCommit` 写入文本，编辑中没有 draft 状态，导致尺寸只能在提交后更新。
- `estimateTextNodeSize` 使用固定宽度 160、行高 24、垂直 padding 16，与 DOM 实际 `fontSize: 14`、`lineHeight: 1.25`、上下 padding 20 不匹配，三行文本高度偏大。
- `zoomFromWheel` 无条件 `preventDefault()` 并调用 `zoomAtScreenPoint`，没有检查 `ctrlKey/metaKey`。
- 节点拖动只在 `pointerup` 中派发 `MoveNodesCommand`，`pointermove` 没有渲染预览位置，所以用户看到松手瞬移。

## 修复内容

- 新增编辑 draft 状态：auto 节点编辑时实时用 draft 文本计算尺寸覆盖，blur 后仍只提交一次历史命令。
- 改进 auto 文本尺寸估算：按最短 120、最长 320 的宽度范围估算；行高改为 18，垂直 padding 改为 20；中日韩字符按更宽字符估算。
- `UpdateTextNodeCommand` 对 auto 节点提交完整估算尺寸，不再只改 height。
- `zoomFromWheel` 只在 `Ctrl` 或 `Meta` 按下时缩放；普通滚轮不再缩放画布。
- 新增拖动实时预览：`pointermove` 时用临时 world delta 渲染节点位置，`pointerup` 时提交命令。
- 增加反复拖动仍可见的回归测试，覆盖用户反馈的“拖拽几次后节点消失”路径。
