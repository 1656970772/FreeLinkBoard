## 追加：Tab linked node 生成位置修复

- 用户反馈：从同一个节点连续 Tab 时，新节点会在源节点上方和下方堆叠生成。
- 多 agent：Ampere 只读调查，确认根因在 `findLinkedNodePosition` 的候选顺序，而不是 command 层或 BoardCanvas Tab 事件。
- 根因：旧算法固定首选 X，只在 Y 方向按 `+88/-88/+176/-176...` 搜索空位；首选右侧槽位被占后，就会围绕源节点上下发散。
- 修复：`linkedNodePlacement.ts` 改为同一行优先向右搜索最多 16 个槽位，横向候选都被占时才进入上下 fallback。
- 测试：

## 追加：Ctrl+L 连线实时预览

- 用户反馈：按下 `Ctrl+L` 后应立即出现一根线，线从选中节点伸出，终点为鼠标位置，并随鼠标移动实时跟随。
- 来源：设计规格 `docs/superpowers/specs/2026-05-14-freelinkboard-design.html` 已要求 `Ctrl+L` 进入连线预览，线从节点边缘伸出并跟随鼠标移动。
- 根因判断：当前 `BoardCanvas` 只有 `linkSourceNodeId` 状态，真正的 edge 只在点击目标节点或空白画布时创建；鼠标移动时没有保存当前预览终点，也没有把临时 edge 传给 `EdgeCanvasLayer` 绘制。
- 修复：
  - `BoardCanvas.tsx` 新增 `latestPointerWorldPointRef` 和 `linkPreviewPoint`。
  - `Ctrl+L` 进入连线模式时，使用最近鼠标位置初始化预览终点；若没有最近鼠标位置，则给源节点右侧一个兜底预览点。
  - 鼠标移动时更新 `linkPreviewPoint`，并构造只用于渲染的 `__link-preview-edge` 临时 edge；该 edge 不写入 `board.edges`，点击落点后才通过 `CreateEdgeCommand` 创建正式 edge。
  - `Esc`、撤销/重做、Tab 创建节点和正式创建 edge 时清理预览状态。
- 测试：
  - `BoardCanvas.interactions.test.tsx` 新增 `previews a Ctrl+L edge from the selected node to the live mouse position`，覆盖：预览线从节点边界出发、终点为鼠标位置、鼠标移动后终点实时更新、预览阶段不污染 `board.edges`。
