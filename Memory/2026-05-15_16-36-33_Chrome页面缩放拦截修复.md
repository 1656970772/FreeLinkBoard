# Chrome 页面缩放拦截修复

## 用户反馈与证据

- 用户反馈：鼠标在同一个节点上，缩放到最小再还原到最大时，鼠标在节点内部的位置仍有漂移。
- 用户补充证据：视频 `C:/Users/Administrator/Videos/屏幕录制/屏幕录制 2026-05-15 162500.mp4` 中，t=4s 右上角出现 Chrome 页面缩放浮层 `125%`，t=8s 又显示 `100%`。
- 我的判断：画布几何锚点测试本身已通过，但 Chrome 页面 zoom 同时变化会改变 DOM 像素坐标系，导致节点相对鼠标产生必然漂移。

## 调试记录

- 现有 `zoomViewportAtScreenPoint` 与 `useCanvasViewport.zoomByScreenPoint` 能保持 screen point 下的 world point。
- 现有极限缩放回归测试仍然通过，说明问题不在纯 viewport 几何公式。
- 视频抽帧也能看到 Chrome 自带页面缩放浮层，和用户补充证据一致。

## 修复内容

- `src/renderer/board/BoardCanvas.tsx`
  - 移除 React `onWheel` 双处理路径。
  - 在 canvas DOM 元素上注册原生 `wheel` listener，选项为 `{ passive: false }`。
  - 在 native listener 内执行 `preventDefault()` 后再调用应用自己的 `zoomByScreenPoint`。
  - 组件卸载或 handler 更新时清理 listener。
- `tests/renderer/board/BoardCanvas.interactions.test.tsx`
  - 新增回归测试：画布必须注册非 passive wheel listener，避免 Chrome Ctrl+wheel 页面缩放。
