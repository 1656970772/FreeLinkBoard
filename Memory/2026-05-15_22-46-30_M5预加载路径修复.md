# M5 预加载路径修复记录

创建时间：2026-05-15 22:46:30

## 用户反馈

- 打开应用后首页显示 `Electron file API is unavailable.`。
- 用户反馈功能全坏，并要求开启子 agent 修复。

## 根因

- `package.json` 使用 `"type": "module"`。
- electron-vite 将 preload 构建为 `out/preload/index.mjs`。
- 主进程原先的 BrowserWindow preload 路径指向 `../preload/index.js`，导致 preload 没加载。
- `src/preload/index.ts` 里的 `contextBridge.exposeInMainWorld("freeLinkBoard", api)` 没执行，所以 renderer 里 `window.freeLinkBoard` 缺失。

## 修复

- 新增 `src/main/windowPaths.ts`。
- `resolvePreloadPath(mainBundleDir, appRoot)` 优先使用 bundled `../preload/index.mjs`。
- 如果 bundled 路径不存在，则 fallback 到 dev 输出 `out/preload/index.mjs`。
- `src/main/index.ts` 的 BrowserWindow 改用 `resolvePreloadPath(__dirname)`。
- 新增 `tests/main/windowPaths.test.ts`，覆盖：
  - bundled `out/main -> out/preload/index.mjs`。
  - dev `src/main -> out/preload/index.mjs` fallback。
  - preload 文件尚未存在时仍返回预期 bundled 路径。

## 验证

- `npm.cmd test -- tests/main/windowPaths.test.ts` 通过，3 tests。
- `npm.cmd run build` 通过。
- 已关闭旧 Electron/dev 进程并重新启动新窗口。
- `npm.cmd test` 通过，24 个 test files / 180 tests。
- `git diff --check` exit 0，仅有 Windows 行尾提示。

## 我的判断

该错误是 preload 文件扩展名与运行时引用路径不一致导致的系统性启动问题，不是 renderer store 或 M5 功能本身坏掉。当前修复锁住了 main/preload 的运行时契约，能防止 `window.freeLinkBoard` 再因 `.js` / `.mjs` 路径不匹配而缺失。
